# Project-Tractrix — the drivable editor (C++, inside Frontier)

The goal of this sub-task: open Frontier's own native editor (the Vulkan + ImGui `Project-Zero` host,
duplicated as **Project-Tractrix**), see the ControlVehicle in a scene with a hierarchy, sun/sky and an
inspector, then press **Play** and drive it with WASD + mouse — clearcoat-with-flakes body, visible XPBD
tyres, default course of a checker plane + ramp + speed bumps.

This is **not** a browser/three.js toy. Every piece below is engine-native C++ that compiles inside the
Frontier tree against the real records (`InstanceRecord`, `TriangleIndex`, `MaterialDescriptor`,
`RigidBodySolver`, `CameraProjection`, `EditorHost`/`OutlinerPanel`/`InspectorPanel`). It cannot be built or
run in the Slate sandbox (no Vulkan / GLFW / Ninja / GPU); it is delivered as Overlay source that drops onto a
Frontier checkout via `Build/DuplicateFromProjectZero.py`, and **you build and drive it locally**.

## How it maps onto the real engine

| Need | Frontier mechanism reused | New Tractrix piece |
|---|---|---|
| Scene in the viewport | `SceneCodec::Encode` → `Content/Scenes/*.gltf`, loaded by `GameExecution` | **`TractrixDriveScene`** (analytic soup, ShowroomStructure discipline) |
| Hierarchy / outliner | `TriangleSpanRecord` → one glTF node per object → `OutlinerPanel` | named spans: Ground, Checker Pad, Ramp, Speed Bump 1‑3, Cone 1‑8, ControlVehicle, Wheel FL/FR/RL/RR |
| Sun / sky | `Project-Zero` celestial sky + `SunInspectorPanel` (inherited unchanged) | — (comes free with the duplicate) |
| Materials | OpenPBR `MaterialSlabDescriptor` + `AutomotiveFlakePaint.slang` (System B) | body = `SlateAutomotiveProfile`/`SlateGlintDensity` + GGX `Coat*` clearcoat |
| Rigid bodies / terrain | `RigidBodySolver` (Jolt, +Z up) + heightfield seam | `TractrixProvingGround` (already committed) |
| Vehicle physics | engine‑agnostic `Vehicle::VehicleSolver` (+ XPBD soft tyre) | already ported (`Engine/PhysicalDynamics/Vehicle/`) |
| Physics → render | `PhysicsInstanceSequence` (poses → `InstanceRecord::World`) | **`VehicleInstanceSequence`** (chassis + per‑wheel spin/steer) — *next* |
| Editor camera | `FlyThroughSolver : CameraProjection` (WASD + RMB look) | inherited |
| Player / chase camera | `CameraProjection` subclass | **`ChaseCameraSolver`** — *next* |
| Vehicle inspector + curves | project `EditorSheet`/`EditorPropertyGroup` via `EditorInspectorSequence.h` | **`VehicleInspectorSheet`** + curve widget — *next* |
| Play → drive | `GameExecution` main loop + `InputExchange` + `DriverInputIntegrator` | **`--scene drive` + Play mode wiring** — *next* |

## Status

### Done (this pass) — verified by isolated compile + a CPU render of the real geometry
- **`Source/ControlVehicleMesh.inl`** — the real `ControlVehicle.blend` exterior shell baked to constexpr
  arrays (1405 verts / 2780 tris), generated by `CarModelling/Tools/MeshToHeader.py`. No wheels (procedural),
  no interior/PROTO parts. Frame: +X fwd / +Y left / +Z up, metres.
- **`Source/TractrixDriveScene.{h,cpp}`** — the default `--scene drive` course, built exactly like
  `ShowroomStructure`:
  - 120 m **checker/grid pad** (visible speed reference), a plain surround underneath;
  - a **ramp** wedge 9 m ahead (6 m run, 1.35 m crest);
  - three rounded **speed bumps** behind the spawn;
  - an eight‑**cone** slalom;
  - the **ControlVehicle shell** in System‑B flake clearcoat (candy‑blue pigment, metallic flakes, low‑roughness
    coat) as one *dynamic* instance, plus four **procedural wheels** (tyre cylinder + hub disc), each its own
    dynamic instance.
  - Emits 5672 triangles across 19 named outliner spans; the dynamic block is contiguous
    (`QueryFirstDynamicInstance()` = chassis, then FL/FR/RL/RR) so the instance sequence can rewrite exactly
    those `World` rows. Wheel rest origins match the GRIT hub table; chassis spawn lifts the shell so the wheels
    rest on the pad at frame zero.
  - Verified: builds clean under `-Wall -Wextra` against engine‑shaped headers; a CPU raster of the generated
    triangles is `../../../../Exhibits/Gallery/Drive/DriveScenePreview.png`.
- **CMake**: `TractrixDriveScene.cpp` added to `PROJECT_TRACTRIX_SOURCES`.

### Remaining (next passes, in order)
1. **`VehicleInstanceSequence.{h,cpp}`** — mirror of `PhysicsInstanceSequence`: each frame, take the
   `VehicleTelemetry` snapshot from `TractrixVehicleScene`, write the chassis `InstanceRecord::World` (rest‑pose
   subtraction like D4) and each wheel's `World` (hub position + steer yaw + rolling spin), rolling `PreviousWorld`
   first for motion vectors / ReSTIR reprojection.
2. **`ChaseCameraSolver.{h,cpp}`** — a `CameraProjection` that trails the chassis (spring‑damped follow, mouse
   orbit), plus a bumper/cockpit option. Editor keeps `FlyThroughSolver`; Play toggles to the chase camera. `C`
   cycles editor ⇄ player.
3. **Vehicle inspector + curve editor** — a project `EditorSheet` bound through `EditorInspectorSequence.h`:
   engine/tyre/aero/brake read‑outs plus an ImGui **curve widget** editing *all* the vehicle curves (engine
   torque, tyre Fx/Fy vs slip, brake fade, aero Cl/Cd, spring/damper), writing straight into the live
   `VehicleSolverConfiguration`.
4. **`GameExecution` wiring** — register `--scene drive` (build `TractrixDriveScene`, spawn
   `TractrixVehicleScene`), pump `InputExchange`→`DriverInputIntegrator`→`scene.AssignInput` on Play, drive
   `VehicleInstanceSequence`, and add the Play/Pause + camera toggle to the control strip.

## Build & drive (on your machine)
```sh
python3 Projects/Project-Tractrix/Build/DuplicateFromProjectZero.py /path/to/Frontier
#   copies Project-Zero → Project-Tractrix, overlays the vehicle engine seam + these Source files
# add to top-level CMakeLists.txt (once):
#   include("${CMAKE_CURRENT_SOURCE_DIR}/Projects/Project-Tractrix/Build/ProjectTractrix.cmake")
cmake --preset linux-app && cmake --build --preset linux-app
# run the drivable course:
./build/linux-app/Project-Tractrix --scene drive
```
